# apps/api/core (TY1 core)

FastAPI app, ADK agent pipeline (intake, parallel planners, solver, check-and-repair loop, narrator), revise and trips endpoints.

Run from `apps/api`: `uv sync && TY_FAKE_LLM=1 uv run uvicorn main:app --port 8080`. Test: `uv run pytest tests/core`.

- `GET /health` returns `{"status": "ok", "version": <GIT_SHA or "dev">}`.
- `POST /plan` takes a `TripRequest` (form) or `PlanText` (`{"text", "lang"}`, free text) and streams `PlanEvent`s as Server-Sent Events (`text/event-stream`). Each frame is `data: <PlanEvent JSON>` and a blank line (`by_alias=True`, so `Leg.from_` is `from`); `: ping` comment lines arrive every 15 s while a step runs. Use `fetch` with a stream reader on the web, since `EventSource` cannot POST.
  - Order: an instant `intake` event (`step` null, sent before any model call); the parsed `intake` (`step` intake); four `planning` events (`step` transport, places, stays, story; any order); `solving`; then `checking` (with `iteration` and `violations`) and, while something is wrong, `repairing` and `checking` again, at most 3 rounds; an optional last `checking` event when leftovers became `Itinerary.warnings`; `narrating`; `done` with the final Itinerary in `partial`, a `plan_id` and a `share_token`.
  - The stream ends after the first `done`, `needs_input` (free text missing origin, destination or dates; up to 3 `questions` and a `draft` TripDraft to pre-fill the form) or `error` (`retryable` says whether trying again may help).
- `POST /plan/{plan_id}/revise` takes a `ReviseRequest` (`lighter_day` with `day`, `swap_stop` with `place_id`, `rain` with an optional `day`, `move_day` with `city`: that destination takes a day from its neighbour and the trip is re-planned) and streams `intake`, `solving`, `checking`, `done` with the same `plan_id` and `share_token`: one trip, a new version (the share link shows the latest). 404 for an unknown plan, 403 for someone else's, 422 when the change does not fit it.
- `GET /plan/{plan_id}` returns `SavedPlan` (`plan_id`, `share_token`, `itinerary`, `version`, `updated_at`) so the owner can reopen a trip editable; 403 when it has another owner. `GET /me/trips` lists one row per trip (old `revised_from` chains show only their newest), most recently changed first, with `mode`, `travellers` and `total_inr`.
- `GET /trips/{share_token}` returns the stored Itinerary, read-only. Trips live in Postgres when `DATABASE_URL` is set (`core/migrations/*.sql`, applied on first connect) and in memory otherwise (lost on restart).
- Accounts (no sign-in yet): `X-Client-Id` header (16–128 of A-Z a-z 0-9 _ -) on `GET /me`, `PUT /me/consents`, `DELETE /me` (202; removes the id's trips, consents and ratings), `GET /me/trips` (newest first) — 401 without it — and optional on `POST /ratings` (201), `/plan` and revise. A finished plan is linked to the id only when its `plan_history` consent is on (on by default for signed-in `fb:` accounts until they turn it off; off for anonymous browsers). `accounts.client_id` is the one place that turns a request into a uid (Firebase can replace it). Postgres via `core/migrations/002_accounts.sql`, memory without `DATABASE_URL`.
- Sign-in (HQ V3-AG): `Authorization: Bearer <Firebase ID token>` is verified in `core/auth.py` (google-auth, Google's public certificates, `TY_FIREBASE_PROJECT_ID`; without it every Bearer is 401 "sign-in is not configured"). Accounts are `fb:<uid>`; a bad token is 401, never a fall-back. The first signed-in call that also sends the browser's `X-Client-Id` moves that browser's trips, ratings and consents to the account, once (`account_links`, migration 003).
- `DELETE /plan/{plan_id}` → 204/404; plans with an owner need that caller (403). A share token cannot delete.
- `Itinerary.season_notes`: TY2's quoted season notes (`guide.season.notes_for`) for each city and month, with source URLs; empty when the sources say nothing.
- `TY_CORS_ORIGINS`: comma-separated extra CORS origins; `https://travel-yantra.web.app` and localhost on any port are always allowed.
- Time to first event: `TY_FAKE_LLM=1 uv run python -m core.bench_first_event` (in process) or `--url <base>` (over HTTP).
- Free text: form-like messages ("Bengaluru to Goa, 11-14 Dec", Hinglish "se") are parsed without the model (`intake.quick_parse`); other text goes to Flash-Lite once and is cached by normalised text, language and date.
- Journeys: day 1 opens with the outbound journey on the chosen transport option (visits start 30 min after arrival), the last day closes with the journey home (`routes.compare` at 18:00; visits end an hour before). They are `DayPlan.legs[0]` and `legs[-1]` with `Leg.role` outbound, between or home (and readable `Travel: `/`Return: ` notes), cost money per traveller, and move the day's start and end; only stop-to-stop road time counts against `max_travel_hours_per_day`.
- Startup: `main.py` calls each lane package's `warm_up()` in a background thread (the guide loads e5), logging `warm_up <lane> done in X s`; `TY_WARM_UP=0` turns it off (tests do).
- Multi-city: the days are split between destinations in order (`solver.split_days`, or `TripRequest.days_per_destination`); each city is solved on its own places; the first day in each later city opens with the inter-city hop (`DayPlan.legs[0]`, from `routes.compare`, else a road estimate) and a `Travel: ` note. Stays are per city; the budget takes the first stay per check-in date.
- Model calls retry 429 and 503 (3 tries within 20 s, or `timeout_s` per call), logged on `core.llm`.
- `TY_FAKE_LLM=1` selects `FakeModel` (no model or network calls); tests always force it (`tests/conftest.py`). `core/llm.py` is the only module that reads `GEMINI_API_KEY`, `GOOGLE_GENAI_USE_VERTEXAI`, `GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION` (use `global`), `TY_MODEL_FLASH` and `TY_MODEL_LITE`. Other lanes call models through `core.llm.get_model()`.
- Modules: `intake.py` (text to TripRequest, Flash-Lite), `solver.py` (days: clustering, nearest neighbour and 2-opt, opening hours, pace), `checker.py` (budget and typed violations), `repair.py` (one repair pass; `check_and_repair` is the plain-Python twin of the LoopAgent), `steps.py` (one function per agent), `pipeline.py` (ADK wiring and the event stream), `revise.py` (the three revise intents), `trips.py` (trip store).
- Data: places from TY2's `guide.planner` (Karnataka corpus), transport from TY3's `routes.compare`, stays from `routes.stays.rank_stays`; sample data (`fakes.py`) where they have none (Goa).
